# Brief and ownership

Every initial brief and resume carries these fields. Fill them from evidence; label unresolved fields and hold the affected task.

- GOAL: one observable outcome.
- SCOPE: allowed files, excluded files, branch and owned worktree.
- CONTEXT: relevant source, PR, prior decisions and changes since the original request.
- ACCEPTANCE: binary checks, one per line.
- VERIFY: commands, user paths, known prerequisites and proof artifacts.
- TIMEBOX: checkpoint, stop conditions and partial-results handoff.
- FORBIDDEN: money, credentials, publishing, customer sends, destructive operations and other task-specific restrictions unless separately authorized.
- REPORT: actual PR URL, branch, head/base SHA, verdict, what ran and what remains.
- STANDING: source-grounded standing instructions with narrower exceptions. Include no secrets or private unrelated transcripts.

Use existing owners and queue storage. For a multi-day program only, a project directory may hold preferences, append-only overview, unit status, merge frontier, verification ledger, completion inbox, named unresolved gates, decision log and derived status. One writer per file. Completion notices are events to reconcile, not instructions to interrupt unrelated work. Never rename or replace existing storage just to match a screenshot.

Driver mappings:

- Claude Code: use its project skills if supported. A different Claude subagent is not different-family proof. Route independent review to confirmed Codex or Grok.
- Codex: use its project skills if supported and isolated worktrees. Route independent review to confirmed Claude or Grok.
- Jules: load the reviewed workflow through existing repo instructions when skills are unsupported. Return actual model identity or unknown. Route review to a known other family through the coordinator.
- Grok: existing feature owners dispatch complete briefs; confirmed Claude or Codex performs independent review. No paid Cursor workers required.

Each project must return a load/install receipt, actual artifact path and commit, a demonstrated verification run, maker and verifier identity, and its remaining acceptance gaps. Delivery of a prompt proves delivery only.
