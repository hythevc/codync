# Correction and writing

## Correct

Confirm a repeated class of mistakes from at least two actual incidents. Prefer an ownership or API change that prevents the mistake, then types, then lint or CI, then a behavior test. Keep changes within the approved task. Do not delete tests or loosen standards to make a check green. Prove a new check fails on the historical bad case and passes on the corrected case. Record exceptions with source-grounded approval and limits.

## Unslop

Edit prose while preserving meaning, evidence, audience and the user's voice. Use plain words, real source names and whole sentences. Remove filler, inflated vocabulary, forced groups of three, synonym cycling, vague claims, stock chatbot phrases, decorative headings, curly quotes and long-dash punctuation. Split dense sentences. Name what the code does and what the evidence measured. Keep material uncertainty rather than removing it as excessive hedging. This is prose cleanup, not permission to refactor code or to send a message.
